# 交戦地レシピ（型カタログ）v0.1

**この文書の役割**: ステージ設計を「毎回ゼロから配置を考える」から「型を選んで刺す」に変えるための基礎資料。ここに書かれているのは、シム実測で裏が取れた事実と、小松の設計判断のみ。推測は書かない。

**作成日**: 2026-07-26

---

## 0. 基本の考え方

ステージの難しさは、交戦地1箇所の中身ではなく **交戦地をいくつ、どれだけ詰めて並べるか** で作る。1箇所あたりの上限は敵4体（鳥のみ例外）。

型は「交戦地1箇所で起きること」の単位。MAPや導線が変わっても、型の中身は変わらない。

---

## 1. 確定した計算式（実測済み）

### 1-1. 撃破時間

```
撃破時間 ＝ (発数 − 1) × 連射間隔 ＋ 0.3秒
発数 ＝ ceil(敵HP ÷ タワーの攻撃力)
```

**0.3秒は弾が飛ぶ時間。1発目に待ち時間はない**（敵が交戦対象になった瞬間に撃つ）。

検証: サラリーマン2発（実測1.05秒）／デブ6発（実測4.3秒）。発数が3倍違っても一致。

### 1-2. 交戦時間

```
交戦時間 ＝ (450 − 85) ÷ (護衛speed + 敵speed)
```

護衛範囲円は450pxだが、**ゾンビは85px手前から攻撃を届かせる**ため、実際に使えるのは365px分。

検証: サラリーマン(speed50)で3.65秒／デブ(speed25)で4.85秒。速度が倍違っても一致。

### 1-3. normalタワー基準値

| 項目 | 値 |
|---|---|
| 攻撃力 | 50 |
| 連射間隔 | 0.8秒 |
| 射程 | 250px |
| 費用 | 100G |

## 2. 確定した法則

### 2-1. すり抜けた敵の扱いは、速度差で決まる

```
敵speed ＜ 護衛speed → すれ違いざまに数回殴られて終わり（振り切れる）
敵speed ＞ 護衛speed → 護衛が死ぬまで殴られ続ける
```

検証: サラリーマン(50)・デブ(25)は数回で終了。キックボード(90)は8回殴り続けて護衛死亡。

**含意**: キックボード(90)・鳥(70)は「取り逃がしたら追いかけてくる敵」。ただし護衛を追って前進するため、**進行方向前方に置いたタワーが保険として機能する**。

護衛speed一覧: dad50 / mom65 / son70 / grandma35 / cat75

### 2-2. 敵を出す間隔が、タワーの連射間隔より広いと余裕が生まれる

タワーは0.8秒に1発しか撃てない。**敵が0.8秒以上の間隔で来ると、タワーは待ち時間が発生せず順番に処理できてしまう。**

検証（鳥8体・normal1基・同一条件）:

| 出す間隔 | 結果 |
|---|---|
| 0.8秒 | HP残100% / CLOSE_CALL 0回（余裕） |
| 0.1秒 | HP残90% / CLOSE_CALL 3回（ギリギリ） |

**含意**: 型の難易度は「敵の数」ではなく「**密度**」で決まる。同じ数でも間隔で別物になる。型には必ず出す間隔を書くこと。

### 2-3. タワーは道から150px以内に置く

射程250pxのnormalの場合:

| 道からの距離 | 撃てる時間 |
|---|---|
| 0〜100px | フル性能 |
| 150px | 約9割 |
| 200px | 約7割 |
| 225px以上 | 実質使用不可 |

**射程の6割より近くに置く**が目安。

### 2-4. 交戦地が近いと、タワー1基で両方カバーできる

2つの交戦地の中間にnormalを1基置いた場合:

| 交戦地の間隔 | 効果 |
|---|---|
| 4マス以内 | **両方フルカバー**（1基で2基分の仕事） |
| 5マス | 約9割 |
| 6マス | 約7割 |
| 7マス以上 | 半分以下 |

sniper(射程350)なら6マスまで両取り可能。**sniperの存在理由は単体性能ではなく、離れた2箇所を1基で見られること。**

**含意**:
- 交戦地を**5マス以上離せば独立**して扱える
- **4マス以内なら連結パターンとして1個にまとめて解く**必要がある
- 間隔4マス＝「真ん中に1基」が正解／6マス＝「それぞれに置く」が正解。**同じ敵数でも間隔で正解が変わる**。間違えても7割は働くため、上手い人だけが得をする構造になる

## 3. 型の書き方

型には以下を書く。**必要なタワー基数は書かない**（使うタワーと護衛によって変わるため、その場で計算する）。

```
【型名】
　敵の構成 ： 種類と数
　出す間隔 ： 秒
　来る向き ： 正面／横／背後
```

必要基数の計算:

```
必要基数 ＝ ceil(体数 × 撃破時間 ÷ 交戦時間)
```

## 3.5 initial型カタログ（確定・2026-07-26）

### 対象と前提

- **initial型**＝護衛の進路上に敵が最初から立って待機している交戦地。護衛範囲円に入るまで敵は静止している
- まっすぐな道・正面衝突を前提とする
- タワーは **normal（100G）のみ**で計算
- 数値は §1 の確定式から算出

```
必要基数 ＝ ceil(体数 × 撃破時間 ÷ 交戦時間)
余裕率　 ＝ (交戦時間 × 基数) ÷ (体数 × 撃破時間)
```

**採用基準**: 余裕率 1.05〜1.60。この帯を外れるものは型として使わない。

> **注記**: この採用基準は暫定値。実測の裏付けは「余裕率1.13でCLOSE_CALLが1回発生」の1件のみ。実機プレイでの手応えと照合して確定させること。

---

- **鳥（speed70）**: 護衛範囲円の対象外で、事前に対空を備えていたかだけが問われる（§4）

**この2種を体数の型として扱わないこと。**

---

### 使い方

1. 交戦地に置きたい敵と体数を決める
2. **その区間を通る護衛**の列を見て、必要基数を読む
3. 余裕率が1.05〜1.60（★）でなければ、体数を変えるか敵を変える

**同一交戦地を複数の護衛が通る場合は、最も基数を要する護衛に合わせる**か、あるいは意図的に不足させて後続の難易度を上げる。

---

### この表の限界

- **normal専用**。sniperは単体性能ではnormal3基に大きく劣る（同額300Gで処理体数が3〜7倍の差）ため、**離れた2箇所を1基で見る用途以外では使わない**（§2-4）
- **cannon / punch は現状使い道がない**。cannonは1基ならnormalより速いが、2基以上になるとダメージが余りnormalに逆転される（実測: デブ2体をnormal2基が19450msで、cannon2基が20100msで撃破。費用は200Gと400G）。punchは射程100pxのため道の上にしか置けず、連射2.0秒が遅すぎて単体では機能しない。**両者は数値の見直しが必要な課題として残る**
- **ice は型の対象外**。spec06の設計原則どおり、三層検証はice抜きで成立させる。iceはクリアを容易にする救済手段であり、型の必要構成には含めない
- 敵種を混ぜた型（重なり型）は未検証

## 4. 鳥は別枠

鳥は他の敵と根本的に性質が異なるため、通常の型カタログとは分けて扱う。

### 4-1. 鳥の性質（確定）

- **「事前に対空を備えていたか」だけを問う敵**
- プレイヤーは護衛を注視しているため、画面外から来る鳥に気づけない
- 気づいて目で追い、旋回場所が確定し、buildSpotを探して押すまで、**最速でも数秒**かかる
- 旋回6秒のうち、実際に使えるのは**1秒程度**。見てから建てても落とせるのは1〜2体
- **見てから建てた効果は計算に入れなくてよい**

### 4-2. 鳥の被害計算

```
被害 ＝ (鳥の数 − 事前タワーが旋回中に落とせる数) × 12
normal1基は旋回6秒間で7体落とせる
```

検証: 鳥8体・normal1基（事前設置）→ 7体撃破・1体すり抜け・HP残90%。計算と一致。

### 4-3. 鳥の設計ルール

**① 単独で出す。地上の交戦と重ねない**

地上で交戦している最中はプレイヤーの目も指も塞がっており、画面外からの鳥に対応できない。**鳥の前後には空白を作る。**

副次的効果として、**鳥がステージのリズム（緩急）を強制する。**

**② 出す間隔は詰める（0.1秒程度）**

広げるとタワーが待ち時間なく処理できてしまう（2-2参照）。

**③ 旋回場所は固定する**

覚えれば次から事前に備えられる。**ランダムにしてはいけない**（永久に対処不能になる）。

**④ 出す数の上限＝護衛が丸ごと食らっても死なない数**

初見では必ず食らう前提のため、初見即死は避ける。

| 護衛 | HP | 上限 |
|---|---|---|
| dad | 120 | 10体 |
| mom | 90 | 7体 |
| son | 80 | 6体 |
| grandma | 70 | 5体 |
| cat | 60 | 5体 |

**⑤ 旋回点をタワーの射程外に置けば、旋回中は撃たれない**

旋回点とbuildSpotの距離関係が、そのまま鳥の難易度になる。

### 4-4. 鳥に必要な実装（未実装・要発注）

鳥は画面外から来るため、**予告なしでは成立しない**（気づけない敵に読みを問うことはできない）。

| 要素 | 役割 |
|---|---|
| 音 | 「来る」を伝える |
| 画面端の矢印 | 「どこか」を伝える。**鳥の現在位置を指す。旋回場所は示さない** |

矢印を出すタイミングが唯一の難易度ツマミになる（事前に備えていた人には無関係で、備えていなかった人の挽回幅を決める）。

## 6. 未確定・今後の課題

以下は**まだ実測していない**。確定するまで設計の根拠に使わないこと。

- すり抜け1体あたりの被弾回数（まっすぐな道・正面衝突・追いつけない敵で4回という観測はあるが、ステージ1のログでは6回・4回・2回とばらついた。護衛の生存時間やゴール到達で打ち切られるため、**上限としての4回**という理解に留める）
- normal以外のタワーでの型（sniper / cannon / ice / punch）
- 横から・背後から来る型
- 連結パターン（4マス以内に交戦地が並ぶ場合）
- 敵種を混ぜた型（重なり型）
- お金の流れ（型には「2基必要」と書けるが、その時点で200G持っているかはステージ全体の問題。型では解けない）
